本システムは以下の方法で特許を検索しています:

```python

def _execute_patentfield_search(
    self,
    query: str,
    limit: int = 100,
    sort_keys: Optional[List[str]] = None
) -> Tuple[int, List[str]]:
    """PatentField APIで検索実行"""

    headers = {
        'Content-Type': 'application/json',
        'Authorization': f'Bearer {self.pf_api_key}'

    payload = {
        "search_type": "expert",
        "q": query,  # 例: "(FI:G03F7/039601) AND (フッ素含有構造単位)"

        "limit": limit
```

## 技術補足: 日本特許の番号体系

### 番号タイプの違い

| 番号タイプ | 説明 | 例 | PatentFieldフィールド |
|----------|------|----|--------------------|
| **出願番号** | 特許出願時に付与される番号 | JP2011032263A | `app_doc_id` |
| **公開番号** | 出願から約1.5年後に公開される番号 | JP2012171629 | `pub_id` |
| **登録番号** | 審査を経て特許登録された番号 | JP5XXXXXXX | `grant_id` |

### 番号の関係

同じ特許でも複数の番号を持ちます:

```
JP2011032263A (出願番号, 2011年出願)
    ↓ 約1.5年後
JP2012171629 (公開番号, 2012年公開) ← 同じ特許
    ↓ 審査
JP5XXXXXXX (登録番号) ← 同じ特許
```

**重要**:
- PatentField APIの検索では`pub_id`（公開番号）を使用するのが標準
- 分類コード（FI, IPC）は公開番号に紐づいている
- `app_doc_id`（出願番号）でも同じレコードが取得できるが、検索には不向き
