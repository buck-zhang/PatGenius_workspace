## 根本原因の特定

### 原因1: APIの取得件数制限（最重要）⭐⭐⭐

#### 問題の詳細
PatentField APIは検索結果を最大1,000件までしか返しません。

```
G03F7/039. の検索:
  総ヒット数: 13,612件
  取得可能: 1,000件のみ（7.3%）
  → 残り12,612件（92.7%）は取得不可

G03F7/004. の検索:
  総ヒット数: 59,471件
  取得可能: 1,000件のみ（1.7%）
  → 残り58,471件（98.3%）は取得不可
```

#### 影響
紐づき特許4件は、広範なFI検索（G03F7/039., G03F7/004.）の結果13,612件や59,471件の中には含まれているが、PatentField APIのデフォルトランキングで上位1,000件に入っていないため取得できていません。

#### 根拠
- G03F7/039.で検索: 13,612件中1,000件取得、紐づき特許0件
- G03F7/004.で検索: 59,471件中1,000件取得、紐づき特許0件
- これは、紐づき特許が1,000位より下位にランクされていることを示す

---

### 原因2: 本願特許に特化した詳細FI分類の使用⭐⭐

#### 本願特許のFI分類コード（ドンピシャ上位13件）

```
1. G03F7/039601  - 化学増幅機構を有するポジ型レジスト
2. G03F7/038601  - 化学増幅機構を有するネガ型レジスト
3. G03F7/004503A - 化学増幅用酸発生剤
4. G03F7/004501  - 添加剤
5. C08F20/10     - エステル（アクリル酸系）
6. C08F220/10    - エステル（メタクリル酸系）
7. C07C381/12    - スルホニウム化合物
8. C07C309/17    - カルボキシル基含有
9. C09K3/00K     - 酸・塩基
10. C08F212/14    - 異種原子含有
11. C07D321/10    - 縮合環系
12. C07D333/76    - ジベンゾチオフェン
13. C07D307/00    - 5員環複素環
```

#### 問題点
`G03F7/039601`, `G03F7/038601`などは**9桁の非常に詳細な下位分類**です。

```
階層構造:
G03F7       - 写真製版（上位3桁）
G03F7/039   - 光分解可能高分子（上位6桁）
G03F7/0396  - より詳細な分類（上位8桁）
G03F7/039601 - 最も詳細な分類（9桁） ← 本願特許
```

同じフォトレジスト技術でも、わずかに異なる化学構造を持つ特許は`G03F7/039602`, `G03F7/039603`など、**別の9桁コード**に分類されます。

#### 影響
現在の検索は詳細すぎるFI分類を使用しているため、同じ技術分野の特許でも除外されます:

```
検索クエリ（現在）:
(FI:G03F7/039601 OR FI:G03F7/038601 OR ...) AND (キーワード)
           ↑
        9桁の詳細分類

紐づき特許の可能性のあるFI分類:
G03F7/039602, G03F7/039603, G03F7/0397xx, G03F7/004xxx など
           ↑
        わずかに異なる → 除外される
```

### 原因3: 本願固有のキーワードの使用⭐⭐

#### 本願特許の検索キーワード（ドンピシャ、構成要素1a）

```
構成要素1a（式(a4)と式(a5)を含む樹脂）:
  - フッ素含有構造単位
  - ペルフルオロアルキル基含有構造単位
  - 脂環式炭化水素基含有構造単位

構成要素1a-1-2（R4の定義）:
  - R4
  - フッ素原子を有する飽和炭化水素基
  - フッ素化アルキル基
  - 含フッ素アルキル基
```

#### 問題点
`R4`, `式(a4)`, `式(a5)`などは、**本願特許の明細書でのみ定義された記号**です。

```
本願特許（JP2014089440）:
  「式(a4)で表される構造単位」
  「R4はフッ素原子を有する飽和炭化水素基」

紐づき特許A（JP2011032263）:
  「式(I)で表される化合物」  ← 異なる記号

紐づき特許B（JP2012173419）:
  「式(b1)で表される化合物」 ← 異なる記号
  「式(c1)~(c3)で表される化合物」
```

#### 影響
同じ化学構造や機能を持つ特許でも、異なる式番号や記号を使用していれば検出されません:

```
本願特許の検索キーワード:
  AND (キーワード:"式(a4)" OR キーワード:"R4" OR ...)

紐づき特許の実際のキーワード:
  "式(I)", "式(b1)", "X", "Y" など

→ キーワードが一致しないため除外される
```

---

### 原因4: AND検索の厳格性⭐

#### 現在の検索クエリの構造

```
(詳細FI分類) AND (本願固有キーワード)
     ↓             ↓
G03F7/039601   式(a4), R4, 式(a5)
G03F7/038601   フッ素含有構造単位
...            ...
```

#### 問題点
両方の条件が同時に満たされないと検出されません:

```
紐づき特許の例:
  FI分類: G03F7/039602（わずかに異なる）
  キーワード: 式(I)（異なる記号）

結果: どちらの条件も一致しないため除外
```

## 推奨される改善策

### 最優先: ランキング・ページネーション機能の実装

#### 問題
PatentField APIは最大1,000件しか返さないため、広範な検索（13,612件や59,471件ヒット）では大部分の結果を取得できません。

#### 改善案A: オフセット機能の実装
```python
# ページネーションで全結果を取得
def fetch_all_results(query, page_size=1000):
    all_results = []
    offset = 0

    while True:
        # オフセットを使用して次のページを取得
        payload = {
            'q': query,
            'limit': page_size,
            'offset': offset  # ← オフセット機能が必要
        }

        results = api_search(payload)
        all_results.extend(results)

        if len(results) < page_size:
            break

        offset += page_size

    return all_results
```

**注意**: PatentField APIにオフセット機能があるか確認が必要。

#### 改善案B: より詳細な絞り込みクエリ
```python
# 1,000件未満になるまで条件を追加
def search_with_refinement(base_query, keywords):
    # ステップ1: 基本クエリ
    query = base_query  # 例: FI:G03F7/039.
    results = api_search(query)

    if results['n_hits'] > 1000:
        # ステップ2: キーワードで絞り込み
        for keyword in keywords:
            query += f' AND キーワード:"{keyword}"'
            results = api_search(query)

            if results['n_hits'] <= 1000:
                break

    return results['records']
```

def rank_by_similarity(patent_structure, search_results, top_n=500):
    # 本願特許の要約・請求項をベクトル化
    main_vector = vectorize(patent_structure)

    # 各検索結果をベクトル化し、類似度を計算
    scored_results = []
    for result in search_results:

        similarity = cosine_similarity(main_vector, result_vector)
        scored_results.append((result, similarity))

    scored_results.sort(key=lambda x: x[1], reverse=True)

    return scored_results[:top_n]

def broaden_fi_codes(fi_code):
    """
    詳細FI分類を上位階層に広げる

    例: G03F7/039601 → [G03F7/039., G03F7/0396.]
    """
    if len(fi_code) >= 9:
        return [
            fi_code[:7] + '.',  # 上位6桁 + ワイルドカード
            fi_code[:8] + '.'   # 上位7桁 + ワイルドカード（中間）
        ]
    return [fi_code]

## 結論

### 主要な原因（確定）

1. **APIの取得件数制限**（最重要）
   - PatentField APIは最大1,000件しか返さない
   - G03F7/039.の検索で13,612件ヒットするが、1,000件しか取得できない
   - 紐づき特許は1,000位より下位にランクされている可能性

2. **詳細すぎるFI分類の使用**
   - G03F7/039601など9桁の詳細分類は本願特許に特化
   - 紐づき特許はG03F7/039602など、わずかに異なるFI分類の可能性
   - 詳細分類を使用する限り、類似特許を除外する

3. **本願固有のキーワードの使用**
   - 式(a4), R4などは本願特許の明細書でのみ使用される記号
   - 紐づき特許は式(I), 式(b1)など異なる記号を使用
   - 固有記号を使用する限り、他の特許を検出できない

### 最優先アクション

**アクション1**: PatentField APIのページネーション・オフセット機能を確認
- ドキュメント調査
- オフセット/ページパラメータのテスト
- 全結果取得の実装

**アクション2**: 検索戦略の階層化を実装
- 広範なFI（G03F7/039.）+ 汎用キーワード
- ヒット数を1,000件未満に絞り込む
- 類似度ランキングの実装

**アクション3**: キーワード抽出ロジックの改善
- 本願固有記号（式(a4), R4など）を除外
- 汎用的な技術用語を優先
- 上位概念キーワードの使用
