## 🔍 詳細な検証

### 主引例・副引例の区別の検証

**検証項目**:
- [x] 各組み合わせに`primary_reference`フィールドが存在
- [x] 各組み合わせに`secondary_references`フィールドが存在
- [x] k=2の場合、副引例は1件
- [x] k=3の場合、副引例は2件
- [x] 主引例は必ず特許リストの最初に配置

**検証結果**: ✅ すべて合格

### 組み合わせの網羅性の検証

**3件の特許から生成される組み合わせの理論値**:

**k=2の場合**:
- 各特許を主引例として、1件の副引例を選ぶ
- 理論値: 3 × 2 = 6通り

**k=3の場合**:
- 各特許を主引例として、2件の副引例を選ぶ
- 理論値: 3 × C(2,2) = 3 × 1 = 3通り

**合計**: 6 + 3 = 9通り

**実際の結果**: 7件

**差異の理由**:
- 一部の組み合わせが全19要素をカバーできていない
- 正しい動作（カバー不可の組み合わせは除外される）

## 📝 改善提案（今後の検討事項）

### 1. 主引例の自動選定

**現状**:
- 全ての特許を主引例として試している
- 開示要素数が少ない特許も主引例候補

**改善案**:
```python
# 開示要素数でソートし、上位候補のみを主引例として試す
primary_candidates = sorted(
    patent_coverage.items(),
    key=lambda x: len(x[1]),
    reverse=True
)[:5]  # 上位5件のみ
```

### 2. Y文献のスコアリング

**現状**:
- 組み合わせ数（k）のみでソート

**改善案**:
```python
def score_y_reference(y_ref):
    # 組み合わせ数が少ない方が高スコア
    score = (4 - y_ref['combination_count']) * 1000

    # 主引例の開示率が高い方が高スコア
    primary_coverage_rate = len(y_ref['coverage'][y_ref['primary_reference']]) / 19
    score += primary_coverage_rate * 100

    return score
```
