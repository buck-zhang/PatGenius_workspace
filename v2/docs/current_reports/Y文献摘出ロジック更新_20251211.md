## 📋 更新概要

### 主要な変更点

Y文献（進歩性欠如文献）の摘出ロジックを以下の戦略に変更しました：

1. **k=1（単独特許）の除外**
   - 以前: k=1, k=2, k=3の組み合わせを全て探索
   - 変更後: k=2, k=3のみ（k=1は除外）

2. **主引例 + 副引例の明確な区別**
   - 以前: 単純な組み合わせ（主引例・副引例の区別なし）
   - 変更後: 各特許を主引例として、最大2件の副引例と組み合わせる

3. **3段階優先度システムの導入**
   - 優先度1（最優先）: 独立請求項の構成要素
   - 優先度2（フォールバック1）: 主要な構成要素（重要度>=0.8）
   - 優先度3（フォールバック2）: 全ての構成要素

4. **フォールバック戦略の明確化**
   - 全ての構成要素の組み合わせがなければ、主要な構成要素の組み合わせで出力
   - それでもなければ独立請求項の組み合わせの結果を出力

### 1. Y文献摘出メソッドの更新

**ファイル**: `src/novelty_assessment_engine.py`
**メソッド**: `extract_y_references()`
**行番号**: 475-551

#### 変更前のロジック

```python
def extract_y_references(self, comparison_results, element_ids, max_combination=3):
    """従来のロジック: k=1,2,3の全組み合わせ"""

    # 各特許がどの構成要素を開示しているかをマッピング
    patent_coverage = {...}

    # Y文献候補を探索
    y_references = []

    for k in range(1, max_combination + 1):  # k=1,2,3
        for combo in combinations(patent_coverage.keys(), k):
            # 組み合わせでカバーされる構成要素の論理和
            combined_coverage = set()
            for patent_id in combo:
                combined_coverage |= patent_coverage[patent_id]

            # 全ての対象構成要素がカバーされているか
            if combined_coverage == element_ids:
                y_references.append({
                    "patents": list(combo),
                    "combination_count": k,
                    "coverage": {...}
                })

    return y_references
```

**問題点**:
- ❌ k=1（単独特許）が含まれる（X文献と重複）
- ❌ 主引例と副引例の区別がない
- ❌ どの特許が主要な役割を果たしているか不明

#### 変更後のロジック

```python
def extract_y_references(self, comparison_results, element_ids, max_combination=3):
    """
    新ロジック（v2.1.1+）:
    - k=1（単独特許）は除外
    - k=2, k=3: ある特許を主引例として、最大2件の副引例と組み合わせる
    """

    # 各特許がどの構成要素を開示しているかをマッピング
    patent_coverage = {}
    for result in comparison_results:
        patent_id = result.get('target_patent_id')
        element_comparisons = result.get('element_comparisons', [])

        disclosed = set()
        for elem in element_comparisons:
            if elem.get('is_disclosed', False) and elem['element_id'] in element_ids:
                disclosed.add(elem['element_id'])

        if disclosed:  # 少なくとも1つの構成要素を開示
            patent_coverage[patent_id] = disclosed

    # Y文献候補を探索（主引例 + 副引例の戦略）
    y_references = []

    # k=2, k=3のみ（k=1は除外）
    for k in range(2, max_combination + 1):
        # 各特許を主引例として試す
        for primary_patent in patent_coverage.keys():
            # 副引例の候補（主引例以外）
            secondary_candidates = [p for p in patent_coverage.keys() if p != primary_patent]

            # 副引例の組み合わせ（k-1件: 1件または2件）
            for secondary_combo in combinations(secondary_candidates, k - 1):
                # 主引例 + 副引例の組み合わせ
                combo = [primary_patent] + list(secondary_combo)

                # 組み合わせでカバーされる構成要素の論理和
                combined_coverage = set()
                for patent_id in combo:
                    combined_coverage |= patent_coverage[patent_id]

                # 全ての対象構成要素がカバーされているか
                if combined_coverage == element_ids:
                    y_references.append({
                        "patents": combo,
                        "primary_reference": primary_patent,  # ✅ 主引例を明示
                        "secondary_references": list(secondary_combo),  # ✅ 副引例を明示
                        "combination_count": k,
                        "coverage": {
                            pid: list(patent_coverage[pid])
                            for pid in combo
                        }
                    })

    # 組み合わせ数でソート（少ない方が優先）
    y_references.sort(key=lambda x: x['combination_count'])

    return y_references
```

**改善点**:
- ✅ k=1を除外（X文献との重複を防止）
- ✅ 主引例（primary_reference）と副引例（secondary_references）を明示
- ✅ 各組み合わせにおける特許の役割が明確
- ✅ 出力JSONに主引例・副引例の情報を含む

### 3. フォールバック戦略の更新

**ファイル**: `src/novelty_assessment_engine.py`
**メソッド**: `_apply_fallback_strategy()`
**行番号**: 716-750

#### 変更前（2段階）

```python
def _apply_fallback_strategy(
    self,
    x_all, y_all,
    x_independent, y_independent
) -> Tuple[List[str], List[Dict], str]:
    """
    フォールバック戦略の適用（2段階優先度システム）

    優先度:
    1. 全構成要素（最優先）
    2. 独立請求項の構成要素（フォールバック）
    """
    # 優先度1: 全構成要素で見つかった場合
    if x_all or y_all:
        return x_all, y_all, "priority_1_all_elements"

    # 優先度2: 独立請求項の構成要素で見つかった場合（フォールバック）
    if x_independent or y_independent:
        return x_independent, y_independent, "priority_2_independent_elements"

    # 何も見つからなかった場合
    return [], [], "no_matching_references"
```

#### 変更後（3段階）

```python
def _apply_fallback_strategy(
    self,
    x_independent, y_independent,
    x_major, y_major,
    x_all, y_all
) -> Tuple[List[str], List[Dict], str]:
    """
    フォールバック戦略の適用（3段階優先度システム）

    優先度（Y文献摘出のための戦略）:
    1. 独立請求項の構成要素（最優先）
    2. 主要な構成要素（重要度>=0.8）（フォールバック1）
    3. 全ての構成要素（フォールバック2）

    フォールバックロジック:
    - 全ての構成要素の組み合わせがなければ、主要な構成要素の組み合わせで出力
    - それでもなければ独立請求項の組み合わせの結果を出力
    """
    # 優先度3: 全ての構成要素で見つかった場合（最も厳格な判断）
    if x_all or y_all:
        return x_all, y_all, "priority_3_all_elements"

    # 優先度2: 主要な構成要素で見つかった場合（フォールバック1）
    if x_major or y_major:
        return x_major, y_major, "priority_2_major_elements"

    # 優先度1: 独立請求項の構成要素で見つかった場合（フォールバック2）
    if x_independent or y_independent:
        return x_independent, y_independent, "priority_1_independent_elements"

    # 何も見つからなかった場合
    return [], [], "no_matching_references"
```

**フォールバックの順序**:
```
全ての構成要素（19要素）で探索
  ↓
  X文献 or Y文献が見つかった？
  ↓ Yes → priority_3_all_elements を採用
  ↓ No  → 次の優先度へ
主要な構成要素（16要素、重要度>=0.8）で探索
  ↓
  X文献 or Y文献が見つかった？
  ↓ Yes → priority_2_major_elements を採用
  ↓ No  → 次の優先度へ
独立請求項の構成要素（8要素）で探索
  ↓
  X文献 or Y文献が見つかった？
  ↓ Yes → priority_1_independent_elements を採用
  ↓ No  → no_matching_references
```

## 🎯 実装の意義

### 1. 特許審査実務との整合性

**日本特許庁の審査基準**:
- 進歩性の判断では、主引例（最も近い先行技術）を選定
- 副引例を組み合わせることで、本願発明の全構成要素が開示されているか判断

**本実装の対応**:
- ✅ `primary_reference`: 主引例を明確に指定
- ✅ `secondary_references`: 副引例（最大2件）を明確に指定
- ✅ 審査基準に準拠した論理構造

### 2. フォールバック戦略の実務的合理性

**優先順位の理由**:

| 優先度 | 対象 | 理由 | 実務的意義 |
|--------|------|------|-----------|
| **優先度3** | 全構成要素（19要素） | 最も厳格な判断 | 真の新規性喪失・進歩性欠如リスク |
| **優先度2** | 主要構成要素（16要素） | 技術的に重要な部分 | 実質的な特許性の判断 |
| **優先度1** | 独立請求項（8要素） | 基本的な技術思想 | 最小限の保護範囲の確保 |

**フォールバックの実用性**:
```
全構成要素で見つからない
  ↓
主要な構成要素で見つかった
  → 技術的に重要な部分は先行技術に開示されている
  → 拒絶理由通知のリスクあり
  → 対応策の検討が必要
```

### 3. 効率性の向上

**組み合わせ数の削減**:

- **変更前**: k=1, k=2, k=3の全組み合わせ
  - n=10の場合: C(10,1) + C(10,2) + C(10,3) = 10 + 45 + 120 = 175通り

- **変更後**: k=2, k=3の主引例+副引例
  - n=10の場合:
    - k=2: 10 × 9 = 90通り（各特許を主引例として、1件の副引例を選ぶ）
    - k=3: 10 × C(9,2) = 10 × 36 = 360通り（各特許を主引例として、2件の副引例を選ぶ）
    - 合計: 450通り

**組み合わせ数は増加するが**:
- ✅ 主引例の役割が明確（審査実務に整合）
- ✅ X文献との重複なし（k=1除外）
- ✅ 各組み合わせの意味が明確

## 🔄 今後の改善案

### 1. 主引例の自動選定

**現在の実装**:
- 全ての特許を主引例として試す
- 組み合わせ数が多い

**改善案**:
- 開示要素数が最も多い特許を主引例候補として優先
- 主引例候補のスコアリング（開示率 × 重要度の合計）
- 上位N件の主引例候補のみを試す
