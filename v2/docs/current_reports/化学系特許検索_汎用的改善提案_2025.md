**作成日**: 2025-12-08
**対象**: 化学系特許全般（有機化合物、高分子、無機化合物、医薬品等）
**目的**: 最新の開発実践に基づく汎用的な検索精度向上策の提示
**参考文献**: 2025年最新のweb情報、WIPO IPC 2025ガイド、特許庁資料

---

## エグゼクティブサマリー

### 2025年時点での化学系特許検索の課題

1. **化学物質名の表記揺れ**: IUPAC名、慣用名、商品名、開発番号の多様性
2. **分類体系の複雑性**: IPC/FI/Fタームの約50万エントリーから適切な選定
3. **技術的多様性**: 同一の技術課題に対する複数のアプローチ（材料設計 vs プロセス最適化）
4. **AI幻覚（Hallucination）**: LLMによる不正確な分類コード・化学物質名の生成

### 本提案の特徴

- **事例非依存**: 特定の特許事例に依存しない汎用的な改善策
- **2025年最新**: WIPO IPC 2025版、特許庁Fターム最新情報（2025年6月）に基づく
- **AI統合**: Human-in-the-Loop（HITL）型のLLM活用ベストプラクティス
- **実装可能**: 現行システムへの段階的導入が可能

## 1. 化学系特許検索の2025年ベストプラクティス

### 1.1 分類体系の統合的活用

#### A. IPC/FI/Fタームの特性理解

| 分類 | エントリー数 | 特徴 | 化学系での活用 |
|------|------------|------|--------------|
| **IPC** | 約70,000 | 国際標準、100カ国以上で使用 | 広範な初期検索、国際出願対応 |
| **FI** | 約190,000 | 日本独自、IPCの細分化 | 日本特許の詳細検索 |
| **Fターム** | 約330,000 | 多観点検索、テーマコード約3,400 | 技術的観点ごとの絞り込み |

**出典**: [Japan Patent Office - Classification](https://www.jpo.go.jp/e/system/patent/gaiyo/seido-bunrui/), [日本の特許を特許分類から調べる | 国立国会図書館](https://ndlsearch.ndl.go.jp/rnavi/stm/post_398)

#### B. 2025年の推奨戦略

**基本原則** ([Fタームの分析で技術の用途開発に役立てる方法](https://marketing.techport.co.jp/archives/29573/)より):
1. **FIをメイン、Fタームを補助**として使用
2. **分類のみに依存しない**: キーワード（化学物質名、構造特徴）を必ず併用
3. **最初は広く**: 分類は多めに選定し、段階的に絞り込み

**化学系特有の戦略**:
```
Step 1: 広範囲検索（IPC/FIの上位分類 + 汎用キーワード）
  ↓ 数千〜数万件
Step 2: 技術観点での絞り込み（Fターム + 構造特徴キーワード）
  ↓ 数百〜数千件
Step 3: 化学物質特定（CAS番号 / 構造検索 / 表記揺れ網羅）
  ↓ 目標範囲（50-300件）
```

### 1.2 IPC 2025版の新機能活用

**WIPO IPC 2025版の化学系向上点** ([Guide to the IPC 2025](https://www.wipo.int/edocs/pubdocs/en/wipo-guide-ipc-2025-en-guide-to-the-international-patent-classification-2025.pdf)):

- **化学構造式のハイパーリンク**: 分類定義に化学構造式が追加され、視覚的理解が容易に
- **"Fully Identified" Compounds Rule**: 完全に特定された化合物（正確な化学名または完全な構造式を持つもの）のみ分類
- **2025.08版CPC**: 最新版が発効、化学分類の精度向上

**実装への影響**:
- 分類コード取得時に構造式の視覚情報を活用
- 曖昧な化合物記載の特許は分類が付与されない可能性を認識
- CPC 2025.08版に対応した分類データベースを使用

### 2.2 化学系特許特化型プロンプトテンプレート

#### A. 分類コード選定プロンプト

```markdown
## Context
あなたは化学系特許分類の専門家です。IPC 2025版、日本特許庁FI/Fタームの最新知識を持っています。

## 化学系特許分類の原則（2025年版）

### 1. 技術的多様性への対応（CRITICAL）

化学系特許（組成物、材料、化合物）は、**同一の技術課題に対して複数のアプローチ**が存在します。
以下のアプローチを**すべて考慮**して分類コードを選定してください：

#### アプローチの分類

| アプローチ | 主要分類 | 代表的な技術 | 例 |
|-----------|---------|-------------|-----|
| **材料設計型** | C08, C07C, C07D | 新規化合物・重合体の構造設計 | 新規高分子、フッ素化合物 |
| **製法・プロセス型** | C08F, C08G, C12P | 合成方法、重合プロセス | 触媒重合、バイオプロセス |
| **用途・機能型** | A61K, C09, G03F | 特定用途での使用 | 医薬品、コーティング、レジスト |
| **物性・評価型** | G01N | 分析方法、測定技術 | 構造解析、純度測定 |

### 2. IPC階層の活用

**上位階層から下位階層へ段階的に選定**:

```
サブクラス (例: C07C)
  ↓
メイングループ (例: C07C 309/00 スルホン酸)
  ↓
サブグループ (例: C07C 309/12 エステル化水酸基含有)
```

**推奨手順**:
1. サブクラスレベルで技術分野を特定（例: C07C 有機化合物、C08F 重合体）
2. メイングループで機能分類（例: C07C 309/00 スルホン酸類）
3. サブグループで構造詳細（例: C07C 309/12 エステル化水酸基）

### 3. 化学物質の分類規則（IPC 2025）

#### A. "Fully Identified" Compounds Rule

分類付与の条件:
- ✓ 正確な化学名（IUPAC名または慣用名）
- ✓ 完全な構造式（すべての原子・結合が明示）
- × 不完全な記述（"R = アルキル基"等のマーカッシュ構造のみ）

#### B. 化学構造の階層

優先順位（高→低）:
1. 特定化合物の個別分類（例: C07C 381/12 スルホニウム化合物）
2. 官能基分類（例: C07C 309/00 スルホン酸）
3. 炭素骨格分類（例: C07C 13/00 脂環式化合物）
4. 汎用分類（例: C07C 1/00 有機化合物一般）

### 4. FI/Fタームの選定基準

#### A. FI選定（日本特許向け）

**基本戦略**:
- IPCの細分化版として、より詳細な技術区分を利用
- 記号の読み方: `C08F220/18` → C08F（高分子）220（メタクリル酸エステル）18（カルボン酸との共重合）

**選定数の目安**:
- ドンピシャ: 5-15個
- 上位概念: 3-10個
- 下位概念: 0-5個（詳細化が必要な場合のみ）

#### B. Fターム選定（補助的活用）

**テーマコードの選び方** ([Fタームの分析で技術の用途開発](https://marketing.techport.co.jp/archives/29573/)):

1. **FIに対応するテーマコードを特定**
   - 例: FI `G03F7/004`（感光材料）→ Fタームテーマ `5F043`（フォトレジスト）

2. **多観点での絞り込み**
   - 観点A: 構造・組成（例: 5F043AA01 フッ素含有）
   - 観点B: 用途（例: 5F043BA01 半導体製造）
   - 観点C: 効果（例: 5F043CA01 解像度向上）

3. **数値範囲Fタームの活用**
   - 分子量、温度範囲、濃度等の数値条件で絞り込み
   - 例: 4J002EA01（分子量1000-5000）

**注意事項**:
- Fタームのみでの検索は漏れのリスクあり
- FIと併用し、補助的に活用

### 5. セクション横断的な分類選定

**化学系特許の特徴**: 複数セクションにまたがる技術が多い

| セクション | 内容 | 化学系での活用例 |
|-----------|------|----------------|
| A | 生活必需品 | A61K（医薬品）、A01N（農薬） |
| C | 化学・冶金 | C07（有機化合物）、C08（高分子） |
| G | 物理学 | G03F（フォトレジスト）、G01N（分析） |
| H | 電気 | H01L（半導体）※電子材料の場合 |

**推奨**:
- 本願の主要セクション（例: C）だけでなく
- 用途セクション（例: A, G）も考慮
- "化学（C） OR 用途（A/G）"の併記検索式を構築

#### B. キーワード生成プロンプト

```markdown
## Context
あなたは化学系特許検索のキーワード専門家です。化学物質名の表記揺れ、IUPAC命名法、CAS登録番号に関する最新知識（2025年版）を持っています。

## 化学系キーワード生成の原則（2025年版）

### 1. 化学物質名の表記揺れ対応（CRITICAL）

**化学物質名の種類** ([化学系特許調査の進め方](https://nihon-ir.jp/chemical-patent-search_basic-1/)):

| 種類 | 説明 | 例 | 特許での使用頻度 |
|------|------|-----|----------------|
| **IUPAC名** | 国際純正応用化学連合の体系名 | 2-メチル-2-プロパノール | 低（5-10%） |
| **慣用名** | 一般的に使用される名称 | tert-ブチルアルコール | 高（60-70%） |
| **商品名** | 企業の登録商標 | Tween 80, PGMEA | 中（20-30%） |
| **開発番号** | 企業内コード | ABC-123, Compound A | 低（5-15%） |
| **CAS番号** | Chemical Abstracts Service登録番号 | 75-65-0 | データベース検索で有効 |

**IUPAC命名法の2013年改訂影響** ([化学系サーチャーが知っておきたいIUPAC命名法](https://nihon-ir.jp/searcher-introduction-iupac/)):
- 優先IUPAC名（PIN）として使用できる慣用名が大幅に制限
- "アセトン"、"イソプロピル"等の多くの慣用名が使用不可に
- 一般IUPAC名（GIN）との併用が認められる

**実務的対応**:
```
化学物質Xの場合、以下をすべて生成:
1. IUPAC名（PIN + GIN）
2. 慣用名（複数）
3. 商品名（主要なもの）
4. 英語名のカタカナ表記（複数パターン）
5. 略称・頭字語
6. CAS番号（データベース検索用）
```

## 化学系検索式生成の原則（2025年版）

### 1. 技術的多様性への対応（CRITICAL）

**重要**: 化学系特許は、同一の技術課題に対して複数のアプローチが存在します。

#### 典型的なアプローチパターン

| パターン | 説明 | 分類の傾向 | 例 |
|---------|------|----------|-----|
| **A. 材料設計型** | 新規化合物・材料の構造で課題解決 | C07, C08系 | 新規フッ素含有樹脂で撥水性向上 |
| **B. 製法・プロセス型** | 合成方法・製造プロセスで課題解決 | C08F, C08G, C12P | 新規触媒による重合効率向上 |
| **C. 添加剤・配合型** | 添加剤の選択・配合比で課題解決 | C08K, C09 | 安定剤添加による耐候性向上 |
| **D. 用途・応用型** | 新規用途の発見で価値創造 | A61K, G03F | 既存化合物の新規医薬用途 |

**検索式での対応**:

```
(
  # アプローチA: 材料設計型
  (材料系FI分類) + (構造特徴キーワード)

  OR

  # アプローチB: 製法型
  (製法系FI分類) + (プロセスキーワード)

  OR

  # アプローチC: 添加剤型
  (添加剤系FI分類) + (配合・組成キーワード)

  OR

  # アプローチD: 用途型
  (用途系FI分類) + (効果・性能キーワード)
)
```

### 2. AND条件の制限（重要）

**問題**: 過剰なAND条件で検索漏れ（0件）が発生

**制限ルール**:
- ✓ 最大2層のAND条件まで: `(A) + (B)`
- ✓ OR条件で代替案を併記: `(A + B) OR (C + D)`
- ❌ 3層以上のAND禁止: `(A) + (B) + (C) + (D)` → 0件リスク

**良い例**:
```
(FI:C07C309/00 OR FI:C07C381/00) + (スルホニウム OR スルホン酸塩)
```

**悪い例**:
```
(FI:C07C309/00) + (スルホニウム) + (トリフェニル) + (ヘキサフルオロ) + (アンチモネート)
→ 過度に限定的、0件の可能性大
```

## 3. Human-in-the-Loop（HITL）型の品質管理

### 3.1 2025年のAI活用原則

**出典**: [Advancing patent law with generative AI](https://www.sciencedirect.com/science/article/abs/pii/S0172219025000080), [Applying Generative AI Tools to Patent Law Practice](https://www.mbhb.com/intelligence/snippets/applying-generative-ai-tools-to-patent-law-practice/)

#### A. Human-in-the-Loop（HITL）の必要性

**LLMの限界**:
- 幻覚（Hallucination）: 存在しない分類コード・化学物質名を生成
- 古い情報: 学習データの更新頻度に依存（IPC 2025版等の最新情報不足）
- コンテキスト理解の限界: 化学構造の微妙な違いを誤認識

**HITL戦略** ([Best Practices for AI Prompt Engineering](https://www.certara.com/blog/best-practices-for-ai-prompt-engineering-in-life-sciences/)):
```
Step 1: AI生成 → 分類コード・キーワードのドラフト作成
  ↓
Step 2: 人間検証 → 専門家が行単位でレビュー（line-by-line oversight）
  ↓
Step 3: 修正・承認 → 不正確な箇所を修正、承認
  ↓
Step 4: 検索実行 → 承認された検索式で実行
  ↓
Step 5: 結果評価 → ヒット件数、関連性を評価
  ↓
Step 6: フィードバックループ → AI改善のためのデータ蓄積
```

        # メイングループ/サブグループ
        # C07C309/12 形式

    # Fタームの形式チェック
    elif classification_type == "F_term":
        # 5桁のテーマコード + 2桁の観点 + 2桁の番号

def validate_search_query(query):
    """
    検索式の妥当性検証

    チェック項目:
    1. AND条件の深さ（最大2層）
    2. 括弧のバランス
    3. PatentField構文の正確性
    """
    issues = []

    # AND条件の深さチェック
    and_depth = count_and_depth(query)
    if and_depth > 2:
        issues.append(f"AND条件が{and_depth}層（推奨: 最大2層）")

    # 括弧のバランスチェック
    if query.count('(') != query.count(')'):
        issues.append("括弧の不均衡")

    # 不正な構文チェック
    invalid_patterns = ['AND', 'CL:', 'AB:', 'TI:']  # PatentFieldで使用不可
    for pattern in invalid_patterns:
        if pattern in query:
            issues.append(f"不正な構文: {pattern}")

    return issues
```

**実行後検証**:
- [ ] ヒット件数が目標範囲内（50-300件）
- [ ] Top 20件のサンプルが関連性あるか
- [ ] 0件でないか（過度な絞り込み）
- [ ] 数万件でないか（絞り込み不足）

   - 対策: SMILES記法・InChI形式の活用検討

3. **表記揺れの無限性**
   - すべての表記を事前に網羅することは不可能
   - 対策: 継続的なフィードバックループによる改善

### 6.2 今後の発展方向

1. **構造検索の統合**
   - SMILES記法、InChI形式による部分構造検索
   - SciFinder、Reaxysとの連携

2. **AIモデルの化学系特化**
   - ChemBERTa、MatSciBERTなど化学系特化LLMの活用
   - 分子構造エンコーディングの導入

3. **グローバル展開**
   - 日本特許以外（米国、欧州、中国）への対応
   - 多言語対応（英語、中国語）
