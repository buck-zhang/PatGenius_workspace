## 🚀 主要な変更点

### 1. Y文献摘出ロジックの改善

#### Before（変更前）
```python
# k=1,2,3の全組み合わせを探索
for k in range(1, max_combination + 1):  # k=1,2,3
    for combo in combinations(patent_coverage.keys(), k):
        # 単純な組み合わせ（主引例・副引例の区別なし）
        ...
```

**問題点**:
- ❌ k=1（単独特許）が含まれる（X文献と重複）
- ❌ 主引例と副引例の区別がない
- ❌ どの特許が主要な役割を果たしているか不明

#### After（変更後）
```python
# k=2,3のみ（k=1は除外）
for k in range(2, max_combination + 1):  # k=2,3
    # 各特許を主引例として試す
    for primary_patent in patent_coverage.keys():
        # 副引例の候補（主引例以外）
        secondary_candidates = [p for p in patent_coverage.keys() if p != primary_patent]

        # 副引例の組み合わせ（k-1件: 1件または2件）
        for secondary_combo in combinations(secondary_candidates, k - 1):
            # 主引例 + 副引例の組み合わせ
            combo = [primary_patent] + list(secondary_combo)
            ...
            y_references.append({
                "patents": combo,
                "primary_reference": primary_patent,  # ✅ 主引例を明示
                "secondary_references": list(secondary_combo),  # ✅ 副引例を明示
                ...
            })
```

**改善点**:
- ✅ k=1を除外（X文献との重複を防止）
- ✅ 主引例（primary_reference）と副引例（secondary_references）を明示
- ✅ 特許審査実務に準拠した論理構造

---

### 2. 3段階優先度システムの導入

#### Before（2段階）
```
優先度1: 全構成要素（19要素）      ← 最優先
優先度2: 独立請求項（8要素）       ← フォールバック
```

#### After（3段階）
```
優先度1: 独立請求項（8要素）       ← 最優先
優先度2: 主要構成要素（16要素）    ← フォールバック1
優先度3: 全構成要素（19要素）      ← フォールバック2
```

**フォールバックロジック**:
```
全ての構成要素の組み合わせがなければ
  ↓
主要な構成要素の組み合わせで出力
  ↓
それでもなければ独立請求項の組み合わせの結果を出力
```

**優先順位の理由**:

| 優先度 | 対象 | 要素数例 | 意義 |
|--------|------|----------|------|
| **優先度1** | 独立請求項 | 8要素 | 基本的な技術思想 |
| **優先度2** | 主要構成要素 | 16要素 | 技術的に重要な部分 |
| **優先度3** | 全構成要素 | 19要素 | 最も厳格な判断 |

**新規フィールド**:
- `primary_reference`: 主引例（1件）
- `secondary_references`: 副引例（1件または2件）

## 🎯 期待される効果

### 1. 特許審査実務との整合性

**日本特許庁の審査基準**:
- 進歩性の判断では、主引例（最も近い先行技術）を選定
- 副引例を組み合わせることで、本願発明の全構成要素が開示されているか判断

**本実装の対応**:
- ✅ `primary_reference`: 主引例を明確に指定
- ✅ `secondary_references`: 副引例（最大2件）を明確に指定
- ✅ 審査基準に準拠した論理構造

### 2. 拒絶理由通知の予測精度向上

**優先度3で見つかった場合**:
```
採用された優先度: priority_3_all_elements
→ 全19要素が先行技術に開示されている
→ 新規性喪失または進歩性欠如のリスクが高い
→ 早期に補正案の検討が必要
```

**優先度2で見つかった場合**:
```
採用された優先度: priority_2_major_elements
→ 主要16要素が先行技術に開示されている
→ 進歩性欠如のリスクがある
→ 従属請求項や限定要素の追加を検討
```

**優先度1で見つかった場合**:
```
採用された優先度: priority_1_independent_elements
→ 独立請求項8要素が先行技術に開示されている
→ 基本的な技術思想は公知
→ 詳細な構成要素で差別化を強調
```

### 3. 審査対応の効率化

**Before（変更前）**:
```
Y文献: 37件の組み合わせ
- どの特許が主引例か不明
- 弁理士が手動で主引例を特定
- 対応方針の検討に時間がかかる
```

**After（変更後）**:
```
Y文献: 30件の組み合わせ（各々に主引例・副引例が明示）
- 主引例: JP2012040876、副引例: JP2013224028
- 主引例: JP2013086509、副引例: JP2012040876, JP2015048479
- → 即座に対応方針を検討可能
```

## 💻 使用方法

### コード例

```python
from novelty_assessment_engine import NoveltyAssessmentEngine

# エンジン初期化（変更なし）
engine = NoveltyAssessmentEngine(
    project_id="ttdc-in-house-dev",
    location="global",
    model_name="gemini-3-pro-preview",
    patentfield_key_path="./patentfield_key.json",
    output_dir="./results",
    max_workers=5
)

# 進歩性判断実行（変更なし）
summary = engine.assess_novelty(
    base_patent_structure_file="structure.json",
    search_result_file="search_results.json",
    limit=None  # 全件処理
)

# 結果の確認
print(f"採用された優先度: {summary['priority_level_used']}")
print(f"X文献: {summary['x_references']['count']}件")
print(f"Y文献: {summary['y_references']['count']}件")

# Y文献の詳細確認（新しい出力形式）
for y_ref in summary['y_references']['combinations'][:5]:
    print(f"\n【組み合わせ {y_ref['combination_count']}件】")
    print(f"  主引例: {y_ref['primary_reference']}")
    print(f"  副引例: {', '.join(y_ref['secondary_references'])}")

    # 主引例の開示要素
    primary_coverage = y_ref['coverage'][y_ref['primary_reference']]
    print(f"  主引例の開示: {len(primary_coverage)}要素")

    # 副引例の開示要素
    for secondary in y_ref['secondary_references']:
        sec_coverage = y_ref['coverage'][secondary]
        print(f"  {secondary}の開示: {len(sec_coverage)}要素")
```
